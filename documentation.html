1. Problem Statement

A rapidly growing technology company receives customer requests through voice calls, chat, emails, and web portals. Customers ask about product features, pricing, subscriptions, troubleshooting, warranty, order status, account issues, and service requests.

The company wants to build a unified AI-powered Customer Success Platform that serves as the first point of contact for customers. The platform intelligently understands customer requests, gathers missing information through conversation, retrieves relevant organizational knowledge, determines the appropriate course of action, and completes tasks whenever possible. If sufficient information is unavailable or the request involves sensitive business operations, the system recognizes its limitations and seamlessly transfers the conversation to a human support representative.

Customers often ask follow-up questions, interrupt conversations, change topics midway, and switch between voice and text interactions. The assistant maintains conversational context while providing fast, reliable, and professional responses.

The organization expects the solution to improve customer experience without compromising security, accuracy, or business policies. The system is designed to handle real-world ambiguity, conflicting information, and incomplete customer inputs while remaining scalable for thousands of concurrent users.

Objective & Mission: To design and develop an industry-ready AI platform capable of delivering intelligent customer assistance by making appropriate architectural decisions, effectively utilizing AI technologies, and ensuring a production-quality user experience.

1.2 Project Overview & Purpose

The Intelligent Customer Success & Service Automation Platform is an advanced, omnichannel enterprise customer engagement solution designed to unify real-time browser-based web support, streaming conversational voice interactions, resilient business process orchestration, and human-in-the-loop escalation into a single, cohesive ecosystem. Built as a polyglot system, the platform bridges the gap between conversational artificial intelligence and deterministic enterprise workflow execution.

1.3 The Real-World Problem Answered

Modern enterprise customer service operations frequently suffer from organizational and technological fragmentation. Traditional chat systems rely on rigid decision trees that frustrate users, while standalone LLM conversational agents lack secure, transactional connectivity to core business databases and workflow systems. Furthermore, integrating low-latency conversational audio streaming alongside asynchronous human agent intervention presents severe concurrency, state consistency, and security challenges.

This platform solves these systemic friction points by implementing an architecture where conversational AI handles fluid natural language reasoning and retrieval, while deterministic workflow engines manage business state transactions, retry logic, and compliance approvals.

1.4 Target Audience Breakdown & Benefits

  • For Non-Technical Stakeholders & Business Leaders:
    The system automates high-volume customer inquiries across text and voice channels without human intervention, drastically lowering support operating costs. When complex requests arise (e.g., high-value warranty replacements or refunds exceeding policy limits), the platform automatically escalates to a human support agent with complete conversational context, sentiment evaluation, and fraud risk scoring, ensuring zero customer repeat-explanation and guaranteed policy compliance.
  • For Software Engineers & Solution Architects:
    The project implements a well-bounded polyglot architecture utilizing TypeScript (Next.js/NestJS) for I/O-bound web traffic and API gateways, Python for compute-heavy AI/ML audio processing and LLM graph orchestration, and Temporal for resilient distributed workflows. Clean schema isolation via PostgreSQL domain namespaces, OpenTelemetry distributed tracing, and specialized security shields ensure extensibility, testability, and operational safety.

2. Architectural Style & Core Design Decisions

2.1 Primary Architecture Style: Polyglot Modular Monolith & Specialized Microservices

The system deliberately eschews both monolithic entanglement and premature microservice sprawl. Derived from exhaustive engineering analyses documented in our Architectural Decision Records (ADRs), the platform adopts a Polyglot Hybrid Architecture:

  1. Modular Domain Monolith for Core Business Logic:
    The primary data-processing application is implemented as a modular core service built on NestJS and Fastify. Rather than deploying dozens of separate chat, case, and policy microservices—which introduce network overhead and complex distributed transactions—the core domain is cleanly bounded by logical schema separation inside PostgreSQL (customer, conversation, case_management, policy, audit).
  2. Specialized Domain Microservices for Heterogeneous Workloads:
    Services exhibiting divergent computational requirements, scaling metrics, or linguistic ecosystems are completely decoupled into dedicated microservices communicating over standardized interfaces:
    • AI Orchestrator Service: Built in Python 3.12 with FastAPI and LangGraph to leverage the dominant AI/ML dependency ecosystem and handle non-linear stateful conversational graphs.
    • Voice Service: Built in Python to manage persistent bi-directional binary WebSocket streams (pcm_s16le at 16kHz) and real-time inference (Faster-Whisper STT and TTS synthesis) without blocking general web gateway worker threads.
    • Durable Workflow Worker: Built on the Temporal SDK to handle long-running, asynchronous background processes (e.g., multi-day refund review approvals) that survive service restarts and system failures without losing transaction state.

5.1 Step-by-Step Request Lifecycle Breakdown

  1. Edge Ingestion & Validation:
    Requests from browser applications arrive at the Next.js BFF and are routed to the Core API. Requests undergo immediate bearer token authentication, payload schema validation via Zod, and correlation ID assignment for distributed observability.
  2. Security Scrubbing & Pre-Processing:
    The logging interceptor evaluates payloads against regex-based PII redaction rules, instantly masking credit card figures, social security numbers, and bank details from telemetry streams.
  3. Dialogue Reasoning & Intent Classification:
    The chat turn is dispatched to the AI Orchestrator. The engine checks the prompt against an adversarial attack filter (AI Security Shield). Once verified safe, intent classifiers determine whether the customer seeks simple answers, order status updates, or complex warranty dispute interventions.
  4. Knowledge Grounding (RAG):
    For informational queries, vector embeddings are generated and compared against pre-computed enterprise policy documents stored in PostgreSQL pgvector. Matched passages are supplied as strict domain context to the inference engine to eliminate hallucination.
  5. Deterministic Process Hand-off (When Applicable):
    If the conversation necessitates mutating enterprise state (such as initiating a product return), LangGraph suspends the dialog loop and submits a validated invocation payload to the Core API. The Core API initiates a Temporal durable workflow, guaranteeing execution even in the event of temporary infrastructure failures.
  6. Asynchronous Response Delivery:
    Responses return to the browser client asynchronously. For chat interfaces, textual responses stream character-by-character over HTTP Server-Sent Events (SSE). For voice sessions, generated text is converted to streaming PCM frames delivered directly over active WebSockets.

7.1 PostgreSQL Schema Namespaces

The primary database instance is structured into seven isolated relational namespaces to prevent unauthorized cross-domain data mutations and facilitate future microservice decomposition:

  • customer Schema: Manages core end-user identities, authentication levels, localized preferences, and custom profile metadata.
  • conversation Schema: Records interactive sessions, storing individual message turns, speaker roles (user, agent, assistant), sentiment tags, and intent labels.
  • case_management Schema: Maintains support tickets, escalation trigger justifications, priority levels, and human agent task assignments.
  • policy Schema: Contains organizational rules, product warranty constraints, and multi-dimensional vector embeddings for conversational retrieval.
  • audit Schema: Functions as an append-only cryptographic transaction log tracking administrative overrides, AI tool execution proposals, and policy mutations.
  • workflow_reference Schema: Binds Temporal workflow execution identifiers to business case entities for seamless UI state tracking.
  • notification Schema: Logs outgoing transactional communication delivery states, retry counts, and customer interaction receipts.

8.1 Implemented Resilient Workflows

  1. Warranty Claim Workflow (WarrantyClaimWorkflow):
    Evaluates customer return requests against hardware policy timelines. If the claimed item value falls below an automated confidence threshold ($100) and invoice verification succeeds via the Integration Service, the workflow instantly authorizes replacement shipping and notifies the customer. If validation criteria fail, it generates an escalation entity in the case_management schema and pauses execution pending human agent review.
  2. Refund Review Workflow (RefundReviewWorkflow):
    Orchestrates high-value financial refunds. Enforces a strict Human-in-the-Loop requirement, requiring an agent to execute an explicit cryptographic approval signal via the Agent Console before transactional settlement commands are dispatched to integration adapters.
  3. Order Processing Workflow (OrderProcessingWorkflow):
    Monitors shipment tracking data, handling automated notification dispatch when delivery dates shift or logistics carriers report fulfillment exceptions.

11.1 Implemented Defense Mechanisms

  • AI Security Shield:
    Located inside the AI Orchestrator middleware (security.py), this subsystem intercepts every text conversation turn and transcribed voice input. It uses heuristic analysis and boundary semantics to identify adversarial prompt injection, jailbreak attempts, and instruction override attacks, terminating malicious sessions instantly with protective HTTP 400/429 status codes.
  • Automated PII Redaction Engine:
    Configured across shared Node.js (packages/observability) and Python (python-packages/ai-observability) libraries, explicit regex parsers scan all outbound application log strings and telemetry attributes, masking Social Security numbers, credit card sequences, and sensitive banking data to ensure HIPAA/SOC-2 compliance.
  • Distributed DDoS Rate Limiters & Correlation Tracing:
    Sliding-window algorithms limit ingress request volume across external routing gates. Every inbound request receives a globally unique X-Correlation-ID header that persists across synchronous REST boundaries, NATS message headers, and Temporal workflow payloads, guaranteeing unified distributed tracing.

The repository relies on specific enterprise platform integrations to achieve inference capabilities and business automation:

    The Integration Service implements canonical data transformation contracts designed to communicate with external shipping logistics providers and merchant order databases without coupling internal schemas to vendor-specific APIs.
